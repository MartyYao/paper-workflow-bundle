# Research Topic

> Version: v0.1.0（初始版；后续 GitHub 独立源仓库沿用同一版本号）

## 定位

本技能负责论文阶段 0 的专业工作；`paper-workflow` 只负责读取项目状态、调用本技能、检查成果物和推进阶段，不重复执行本技能的选题方法论。

本技能的目标不是快速生成几个题目，而是把一个候选题目推进到可以由研究者作出知情决策的状态：

```text
重要问题 → 中英文证据边界 → 明确空白 → 创新价值
          → 最小可行研究设计 → 竞争性解释与证伪 → GO / HOLD / KILL
```

## 何时使用

- 用户开始一篇新论文、要求“选题”或寻找新的研究方向；
- 用户已有处理变量、政策冲击或大致方向，需要寻找因变量、机制或真正的研究空白；
- 用户要求比较中英文文献、判断题目是否重复、评估创新性或贡献价值；
- 用户已有初步题目，需要检查数据、识别策略、样本和执行成本；
- 实证论文因意外发现回退到阶段 0，需要把发现重新孵化为新选题。

已有明确研究问题、只需要写综述或运行回归时，不重新启动完整选题流程；由 `paper-workflow` 路由到文献、理论、研究设计或 Stata 技能。

## 与 paper-workflow 的接口

### 输入

先读取：

1. `研究/<项目名>/论文写作/00-项目仪表盘.md`（若已存在）；
2. `研究/<项目名>/论文写作/01-选题/` 中已有短名单、淘汰记录和研究计划；
3. 用户已有论文、博士论文、当前研究方向和明确的发表边界；
4. `agent memory/学术/_设计/` 中与选题直接相关的设计经验；
5. 若由 `research-discovery` 回退而来，读取对应 `研究发现/03-选题孵化.md` 和发现文件。

不要把已有题目的标题当作已验证的研究问题。先区分用户给出的观察、问题、假设、机制、因果估计量和可观测预测。

### 输出

在 `研究/<项目名>/论文写作/01-选题/` 生成或更新：

| 成果物 | 必须回答的问题 |
|---|---|
| `选题检索边界.md` | 检索日期、数据库、关键词、筛选标准、覆盖限制是什么？ |
| `文献全景地图.md` | 谁研究了什么、用什么数据和方法、得到什么结论？ |
| `文献证据台账.csv` | 每一条关键判断由什么来源支持、挑战或限定？ |
| `文献矩阵.md` | 中英文文献在问题、制度、变量、方法和结论上如何对应？ |
| `空白证据备忘录.md` | 现有研究知道什么、真正不知道什么，空白证据在哪里？ |
| `创新价值备忘录.md` | 题目相较已有研究新增什么，结果会改变哪一类知识？ |
| `可行性审计.md` | 数据、样本、处理变异、识别策略和执行成本是否过关？ |
| `竞争性解释矩阵.md` | 至少两个替代解释是什么，什么结果可以区分它们？ |
| `选题短名单.md` | 3—5 个候选方向及其证据化比较、风险和状态。 |
| `淘汰选题记录.md` | 被放弃方向、证据、原因和日期，避免跨会话重复讨论。 |
| `研究计划.md` | 仅在用户确认 GO 后生成，作为阶段 1—5 的权威入口。 |

如果项目目录尚未建立，由 `paper-workflow` 按项目结构创建；本技能不要在没有项目名的情况下擅自写入用户的 Obsidian vault。

## 工作流程

### 0. 建立研究边界

用一句话冻结研究观察：谁、在什么时间、什么制度或政策环境下、出现了什么现象。再写出：

- 研究对象和分析单位；
- 结果变量的经济含义，而不是仅列一个数据库变量名；
- 用户已有的处理变量、数据资产和研究积累；
- 默认发表边界：普通 CSSCI，除非用户另行指定；
- 不可接受的敏感叙事、识别风险和数据限制。

### 1. 先问题后方法

分别生成 problem-first 和 solution-first 两条路径，但优先推进 problem-first：

1. 从现实困惑、制度变化、企业行为或已有结果中提炼研究谜题；
2. 再检查什么数据和识别设计能够回答它；
3. 不因为已有某个 DID、IV 或处理变量，就反向寻找一个可以套用的因变量。

问题必须能够写成：

> 在条件 D 下，已有研究对现象 A 的解释不能说明 B；本研究检验机制 M，识别对象为 E，结果将更新关于 C 的认识。

### 2. 执行中英文文献全景检索

按 `references/evidence-search-protocol.md` 执行，先建立检索边界再扩展文献。至少覆盖三层：

- 精确主题：同一处理变量、结果变量、制度安排和研究对象；
- 邻近机制：相同机制但不同制度，或相同结果但不同处理变量；
- 方法与政策：相同识别策略、同类政策评估和竞争性政策。

中文通道优先加载 `chinese-literature`，使用 CNKI RSS、CNKI 主动检索和 NCPSSD；必要时读取 Zotero 本地库。英文通道使用可用的 `academic-literature-collector`、OpenAlex、Crossref、Semantic Scholar 或 `paper-search-mcp`。工具不可用时如实记录缺口，不把未检索说成未发表。

每条检索必须记录日期、来源、完整查询式、过滤条件、结果范围、纳入/排除理由和证据角色。至少保留支持、挑战和限定三类来源，不能只收集支持候选题目的论文。

### 3. 识别空白而不是制造空白

先把文献按问题、制度、处理变量、结果变量、机制、样本、方法和结论编码，再判断空白类型：事实、机制、理论、制度、测量、方法、结论冲突或外部有效性。

空白声明必须同时给出：

1. 已有共识；
2. 已有研究的边界或矛盾；
3. 本研究新增的条件、机制、预测或测量；
4. 代表性中英文来源；
5. 为什么不是简单复制、换国家或已知关系的两端拼接。

禁止使用以下未经证据支持的表述：

- “没有人研究过”；
- “国内外研究尚未关注”；
- “这是首次发现”；
- “数据和方法是新的，所以具有创新性”。

改写为“在本次检索边界内未定位到……”并明确检索范围和剩余不确定性。

### 4. 评估创新价值

分别记录 novelty 和 contribution：

- novelty：已有研究没有做过什么；
- contribution：如果本研究结果成立，哪个已有认识、理论机制、经验结论或政策判断会被修改。

每个候选题目必须回答：

- 哪篇或哪一组代表性文献会被更新？
- 新预测是什么，为什么制度条件会让预测不同？
- 结果为正、不显著或反向时分别增加什么知识？
- 贡献是理论机制、经验事实、制度解释、测量/数据还是政策含义？
- 贡献价值是否足以覆盖数据整理、识别和发表风险？

不使用一个脱离证据的自动总分替用户选题。可以按“强 / 中 / 弱”做分维度判断，但每个判断必须附证据、风险和待验证事项。

### 5. 完成可行性与识别审计

在进入理论推演前，按 `references/feasibility-identification-audit.md` 做最低限度审计：

- 核心 X、Y、M 和控制变量的实际数据来源与可得状态；
- 样本单位、时间窗口、处理组/控制组和集群数量；
- 处理时点、处理强度和横截面/时间变异；
- 基准识别策略、关键假设、主要威胁和替代设计；
- 变量构造的手工工作量、匹配误差和可复核性；
- 最小可行论文与主设计失败后的备用路径。

CSMAR 自由文本、政策机构名称和省级制度变量必须做口径审计，不能仅凭字段名判断可得。对于政府补贴、政策机构级别、研发操纵和高管文本等复杂变量，保留标准版、严格版或正交验证版的构造方案。

### 6. 生成竞争性解释和证伪条件

在候选题目确认前，至少列出两个真正能解释结果的替代解释，覆盖机制、测量误差、遗漏变量、选择、反向因果或竞争性政策中的相关类别。为主解释和每个替代解释各写可观测预测、相互区分的检验、预期不确定结果和不支持条件。

“做机制检验”不是证伪计划。必须说明：如果主结果不显著、符号反向、处理前趋势失败或只在某一测量口径下成立，题目如何降级、回退或淘汰。

### 7. 候选题目决策门

通常形成 3—5 个候选档案，不直接跳到一个题目。使用以下状态：

- `GO`：空白证据、贡献价值、最低可行设计和证伪条件均已形成，用户确认进入研究计划；
- `HOLD`：问题有价值，但文献边界、数据或识别仍有关键不确定性，列出下一项验证；
- `KILL`：简单复制、贡献价值不足、核心数据不可得、识别无法成立或触犯质量护栏，记录淘汰原因。

只有用户确认 `GO` 后，才由 `paper-workflow` 进入阶段 1 或阶段 2，并生成 `研究计划.md`。本技能提供证据化建议，不替用户作最终学术选择。

## 必须遵守的质量护栏

逐候选题目读取 `references/quality-guardrails.md`。核心要求包括：非简单的两端拼接、非简单跨国复制、制度差异产生新预测、单向故事线、政治与发表安全、与普通 CSSCI 目标匹配、可证伪。

同时遵守：

- 不捏造文献、DOI、样本量、数据字段或检索结果；
- 不把“搜不到”写成“没有”；
- 不以显著性、可发表性或期刊猜测代替学术贡献价值；
- 不把机制、异质性或交互项误写成主研究问题；
- 不在没有最小可行设计的情况下确认题目；
- 不丢弃淘汰方向，必须记录理由和日期。
