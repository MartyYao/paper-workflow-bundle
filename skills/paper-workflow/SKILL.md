# Paper Workflow — 8 阶段论文编排器

## 可用工具

**实证问题排查**：见 §5.1 实证问题溯源。遇到平行趋势/不显著等实证问题时，先加载 `research-discovery` 技能分层诊断（数据层/方法层/理论层），需要外部实操方案时再加载 `research-media-skill` 搜经管之家。

论文流程中涉及 Python 数据处理时，使用独立 conda 环境 `research`：

```bash
# 方式 1：直接调 pyresearch（推荐，已隔离 PYTHONPATH）
pyresearch script.py
pyresearch -c "print('hello')"

# 方式 2：终端工具
terminal("pyresearch -c \"import pandas as pd; ...\"")
```

环境位置：`/opt/homebrew/Caskroom/miniforge/base/envs/research/`
包：pandas 3.0.3, numpy 2.4.6, scipy, matplotlib, openpyxl, requests, jupyter

> ⚠️ 此环境与 Hermes 的 Python 3.11 venv 隔离。通过 `pyresearch` wrapper 调用时会自动清空 PYTHONPATH，避免 3.11 的 numpy .so 污染。

## 核心设计

本 skill 是论文写作的**总调度器**，不替代任何现有工具，而是：
- 读取 Obsidian 项目仪表盘 → 知道当前状态和上下文
- 调用现有 skill（research-topic、meng-skills、aers-index、academic-literature-collector、obsidian 等）
- 在阶段边界写入决策门
- 每次会话结束后更新仪表盘

**阶段 0 的专业能力由 `research-topic` 承担**：本 skill 不直接进行选题检索、空白论证、创新价值评估或可行性审计，只负责传递项目上下文、检查成果物、等待用户确认并推进阶段。`research-topic` 是独立配套技能，见 [MartyYao/research-topic-skill](https://github.com/MartyYao/research-topic-skill)。

### 项目结构

```
研究/<项目名>/                  ← 直接在 Obsidian vault 根目录下（2026-07 由"论文/"更名）
├── 研究发现/                  ← research-discovery 技能空间（实证发现管理）
│   ├── 00-发现索引.md         ← 看板：发现清单 + 状态
│   ├── 01-发现/F-xxx.md       ← 每条发现一个文件（触发→诊断→决策→沉淀）
│   ├── 02-假设修正.md         ← 聚合：假设修正史
│   ├── 03-选题孵化.md         ← 聚合：孵化中的新选题
│   └── 04-方法论沉淀.md       ← 聚合：跨论文可复用经验
└── 论文写作/                  ← 本 skill 空间（原 论文/<项目名>/ 结构整体平移）
    ├── 00-项目仪表盘.md          ← 跨会话状态中枢
    ├── 01-选题/
    │   └── 研究计划.md           ← 研究设计权威文档，随实证更新同步修订
    ├── 02-文献/
    │   ├── 文献综述.md
    │   └── 论文精读/
    ├── 03-理论/
    │   ├── 制度背景.md
    │   └── 理论推演.md           ← 含研究假设（需随实证结果更新）
    ├── 04-数据/
    │   ├── 数据需求清单.md
    │   ├── 数据构造/
    │   └── 分析命令/              ← do 文件 + log + CSV
    ├── 05-实证/
    │   └── 主回归结果.md          ← 全量表（详细系数，非摘要）
    ├── 06-论文稿/
    └── 07-投稿/
```

两个目录通过 wiki-link 双向索引：研究发现文件「触发」段链接论文写作来源文件，「决策与影响」段链接被修改的论文文件；论文写作修改处追加反向标注 `> ⚠️ 依据 [[F-001-标题关键词]] 修正（日期）`。**发现文件命名 `F-序号-标题关键词.md`（序号项目内递增），反向链接必须写完整文件名**——`[[F-001]]` 解析不到 `F-001-标题关键词.md`，会断链。

**关键文件索引（改实证必查）**：

| 改了 do 文件的什么 | 必须同步更新哪些 Obsidian 文件 |
|------|------|
| 新增/删除回归表 | 主回归结果.md、README.md、仪表盘 |
| DV 构造或版本变化 | 研究计划.md（§2.1）、理论推演.md（假设部分）、数据构造/ |
| 处理变量变化 | 研究计划.md（§2.2）、理论推演.md（假设部分）、制度背景.md |
| 经济后果结果变化 | 研究计划.md（§6）、仪表盘 |
| 机制检验结果变化 | 理论推演.md（H2/H3）、仪表盘 |
| 假设方向/数量调整 | 理论推演.md（§四）、研究计划.md（§1.3） |
| 实证结果意外/假设修正 | 研究发现/（F-xxx 文件 + 02-假设修正.md），理论推演.md 修改处追加反向标注 |

## 交互规范（强制执行）

本 skill 下的所有用户交互必须遵守以下两条规则：

### 规则 1：提问用弹窗，不用文字列表

向用户提问时，**必须使用 `clarify` 工具**，不得在回复正文中罗列问题。

```
✅ clarify(question="主回归用哪个版本？", choices=["V1 标准口径", "V2 严格口径", "V1+V2 并列"])
❌ "你想用 V1 还是 V2？还是两个都要？"
```

`clarify` 自动提供可点击选项 + 「Other」自由输入。每次一个问题，逐个确认。

### 规则 2：执行前消歧——先问再做

以下情况**必须先用 `clarify` 提问，等确认后再执行**：

| 触发条件 | 示例 |
|---------|------|
| 指令有多种合理解读 | "把那个回归跑一下"——哪个 DV/样本？ |
| 存在替代方案且有实质差异 | 分组检验 vs 连续变量回归 |
| 操作会改变论文结构 | 删除某张表、移动某节 |
| 结果可能被用户否决 | 跑大概率不显著的回归 |
| 涉及文件覆盖或删除 | 重写 Obsidian 文档、删除旧 CSV |

**不需要提问**：简单数据查看、参数已明确的回归、纯机械操作。

## 依赖自检（会话启动时强制执行，v0.4.0）

本技能依赖 7 个配套技能才能完整运转。**每个新会话的第二步**（读取仪表盘之后、进入任何阶段之前）执行：

### 检查清单

用 `skills_list()` 核对以下技能是否已安装：

| 配套技能 | 缺失时影响 |
|---------|-----------|
| research-topic v0.1.0 | 阶段 0 无法完成双语文献空白、创新价值和可行性审计；不得直接确认新题目 |
| meng-skills | 写作/润色阶段无去 AI 味能力 |
| stata-regression | 阶段 4/5 无法执行 Stata（硬依赖） |
| research-discovery | 实证异常结果无法分层诊断 |
| chinese-literature | 阶段 1 中文文献检索不可用 |
| journal-submission-docx | 阶段 7 无法生成投稿版 docx |
| research-media-skill | 实证问题无法搜经管之家方案 |

### 缺失时自动安装

任一缺失 → 立即执行（不等用户指示）：

```bash

curl -fsSL -o /tmp/pw-install.sh https://raw.githubusercontent.com/MartyYao/paper-workflow-bundle/main/install.sh
bash /tmp/pw-install.sh

# 方式 2：只补缺失的单个技能（同上 zip 方式，手动拷贝）
#   curl -fsSL -o /tmp/pw.zip https://codeload.github.com/MartyYao/paper-workflow-bundle/zip/refs/heads/main
#   解压后拷贝 skills/<技能名>/ 到 ~/.hermes/skills/research/ 对应类别目录
# ⚠️ 不要用 hermes skills install <repo>/skills/<name> —— GitHub API 有未认证限额，
#    且 registry 存在同名 paper-workflow（v0.1.0）可能装错来源（2026-08-13 用户反馈）
```

安装后重跑 `skills_list()` 验证；仍缺失 → 如实告知用户缺失项和影响范围，降级运行（对应阶段明确提示缺什么），不假装功能可用。

> 聚合仓库 `MartyYao/paper-workflow-bundle` 每日自动同步各配套技能源仓库最新版（见其 README）。

## 会话启动协议（强制执行）

**每个新会话的第一步**，读取项目仪表盘和跨 Agent 记忆。

### 步骤 1：项目仪表盘

> ⚠️ **iCloud 同步延迟**：Obsidian vault 在 iCloud 上。程序化创建的文件夹可能不会立即出现在 Obsidian 侧边栏。如果用户说"没看到文件夹"，先用 `ls` 验证磁盘上确实存在，告知用户等待同步或手动在 Finder 中访问该文件夹触发同步。
```text
read_file("研究/<项目名>/论文写作/00-项目仪表盘.md")
```

从仪表盘提取：
- 当前阶段和状态
- 已完成工作和产出
- 本轮待完成任务
- 上次会话的决策和待办
- 关键文件路径

### 步骤 2：跨 Agent 记忆（如存在）

检查 Obsidian vault 根目录下 `agent memory/` 文件夹：
- `agent memory/学术/论文-<项目关键词>/` → 读取，获取论文状态、关键结果、待办
- `agent memory/学术/_方法/` → 仅在遇到 Stata/数据问题时读取
- `agent memory/学术/_设计/` → 仅在选题/研究设计阶段读取

**路由规则**：只读文件夹名匹配当前任务的目录，不读全量。不确定时不读，等任务明确后再加载。发现类经验沉淀统一走 `agent memory/学术/_方法/`（与 research-discovery 一致）。

然后直接进入对应阶段，**不要重新确认用户意图**（仪表盘就是意图记录）。

## 阶段 0：选题设计

**定位**：阶段 0 的中枢入口。专业选题工作全部委托给 `research-topic`，本 skill 只做路由、状态、成果物和决策门。

### 0.1 调用 research-topic

调用前传递：

- 项目仪表盘和当前阶段；
- 用户既有论文、博士论文和研究方向；
- `01-选题/` 中已有短名单、淘汰记录、研究计划；
- `agent memory/学术/_设计/` 中相关设计经验；
- 若由实证发现回退，传递 `研究发现/03-选题孵化.md` 和对应发现文件。

要求 `research-topic` 按其自身 SKILL.md 和 references 完成：问题界定 → 中英文检索 → 证据台账 → 空白论证 → 创新价值 → 可行性审计 → 竞争性解释 → GO/HOLD/KILL。

### 0.2 阶段 0 成果物检查

没有以下成果物，不得把阶段 0 标记为完成：

- `选题检索边界.md`
- `文献全景地图.md`
- `文献证据台账.csv`
- `文献矩阵.md`
- `空白证据备忘录.md`
- `创新价值备忘录.md`
- `可行性审计.md`
- `竞争性解释矩阵.md`
- `选题短名单.md`
- `淘汰选题记录.md`（若存在被淘汰方向）

至少一个候选档案必须通过 `research-topic/scripts/validate_topic_dossier.py`；证据台账必须通过 `validate_evidence_ledger.py`。脚本通过只表示结构完整，不表示空白、贡献或因果识别已经成立。

### 0.3 用户决策门

- `GO`：用户确认某一候选题目，才生成/更新 `01-选题/研究计划.md`，并进入阶段 1 或阶段 2；
- `HOLD`：记录缺失证据、责任动作和截止条件，不得强行进入研究设计；
- `KILL`：把方向和证据写入 `淘汰选题记录.md`，不得在下一次会话中无记录重复提出。

阶段 0 不自动替用户决定题目。`paper-workflow` 只记录用户确认的决策、更新仪表盘，并把 `research-topic` 的检索边界和文献台账传给阶段 1，避免正式综述重新从零开始。

## 阶段 1：文献检索与综述

**定位**：串联现有工具，系统化产出。

### 流程

中文文献通过 `chinese-literature` 技能（三通道策略）完成：

1. **中文文献（被动）**：加载 `chinese-literature` → 运行 CNKI RSS 采集（`scripts/cnki-rss.py`）→ 获取 13 本顶刊最新论文
2. **中文文献（主动·CNKI）**：加载 `chinese-literature` → 按用户需求运行 CNKI 浏览器搜索（JS 注入）→ 含 CSSCI/EI/北大核心高级检索过滤、期刊收录查询、论文详情提取
3. **中文文献（主动·NCPSSD）**：加载 `chinese-literature` → 运行 NCPSSD API 搜索（`scripts/ncpssd-search.py`）→ 开放获取文献，零认证零验证码，全学科覆盖
4. **英文文献**：`academic-literature-collector` 当期 + OpenAlex 追查
5. **精读**：按 AERS 的 literature-review 方法论（PRISMA 2020）筛选
6. **综述撰写**：按主题组织（非作者名单堆砌），存入 `02-文献/文献综述.md`

检查点：
- [ ] 中文覆盖知网核心期刊近 5 年（RSS 监控 + 主动搜索双轨）
- [ ] CSSCI 期刊来源过滤已使用（高级检索 `#CSSCI` 复选框）
- [ ] 英文覆盖对应英文文献
- [ ] 每篇精读有笔记（Obsidian 双向链接）
- [ ] 综述明确了研究空白（为阶段 2 理论分析铺路）

## 阶段 2：理论分析与研究假设

**定位**：质量检查清单为主（A 主线），完整框架生成为可选（B 可选）。
AI 的角色：**展示可能理论路线，由用户选择和完善**。

本阶段详细模板见 `references/theoretical-analysis-template.md`。核心流程：

### 2.1 制度背景

检查清单：
- [ ] 处理变量的制度来源（政策文件/法规/行政命令）
- [ ] 推行时点和地区差异描述
- [ ] 制度细节足够支撑识别策略（为什么某些地区先推行？）

产出：`03-理论/制度背景.md`

### 2.2 理论推演

AI 引导用户探索可能的理论路线：

**第一步：列出候选理论透镜**
从 `references/theoretical-analysis-template.md` 的候选理论透镜速查表中提取至少 3 个，让用户选择。

**第二步：用户选定后，推演逻辑链**
对每个假设，明确：
- X → M1 → M2 → Y 的每步逻辑
- 每步的文献支撑（至少一篇引用）
- 方向预测（正向/负向/非线性）

**第三步：竞争性解释**
- 反向因果是否可能？（Y 变化→X 推行？）
- 遗漏变量？（有其他同时期政策？）
- 替代解释？（不经过你提出的机制，也能解释 Y 变化？）

产出：`03-理论/理论推演.md`，含：
- 选定的理论框架 + 排除的理由（为什么不选另外几个）
- 机制图（X → M → Y）
- H1/H2/H3 的完整表述

### 2.4 假设提出

每一条假设必须满足：
- [ ] 有理论依据（非"已有研究"的模糊引用）
- [ ] 有明确方向预测
- [ ] 可证伪（什么实证结果算"不支持假设"？）
- [ ] 不与已有文献的已知结论冲突（或说明了为什么冲突）

## 阶段 3-5：快速迭代环

这三个阶段形成一个闭环。阶段 5 的结果可能触发射向阶段 3/4/2/0 的回退。**意外结果的处理流程（分层诊断→差距分析→决策路由→沉淀）见 `research-discovery` 技能，发现文件归档于 `研究发现/01-发现/`。**

### 决策门规则

阶段 5 完成后，**逐组件评估**，不是只看主回归 p 值。主回归 p<0.01 但机制/平行趋势/经济后果部分失败是常见情况。

```
══════════ 逐组件决策门 ═══════════

A. 主回归 (H1)
   ✅ DV 全部显著 (p<0.05) 且方向正确
   ⚠️ 部分显著 → 考虑 DV 构造调整 → 回阶段 4
   ❌ 全部不显著 → 回阶段 2 或 0

B. 平行趋势 (事件研究法)
   ✅ 处理前系数不显著异于零（全样本）
   ⚠️ 某些子样本不过 → 如实记录，不是放弃的理由
      - 子样本样本量 < 2000 → 可接受「结构性不过」
      - 符号一致子样本可做辅助证据
   ❌ 全样本不过 → 加载 research-discovery 分层诊断 → 需外部实操方案时加载 research-media-skill 搜经管之家 → 回阶段 3（调整识别策略）

C. 机制检验
   ✅ 三步法全部通过 或 交互项显著
   ⚠️ Step 2 失败 → 检查 M 是否为固定特征
      - 若是（如 pc_any/SOE）→ 三步法不可用，改用交互项
      - 若不是 → 检查 M 构造是否有误
   ❌ 所有机制方案均失败 → 论文无机制可报告 → 回阶段 2

D. 稳健性
   ✅ 至少 2 项稳健性检验通过且系数稳定
   ⚠️ 仅 1 项通过 → 加做 1-2 项
   ❌ 全部不显著 → 主效应不稳健 → 回阶段 4

E. 经济后果
   ✅ 至少 1 项显著
   ⚠️ 全部不显著 → 论文经济含义段单薄，考虑替换变量
      - 常见调整：TobinQ→ROA、专利总量→专利知识宽度
```

### 5.3 实证版本管理协议（强制执行，2026-08-07 定案）

**背景**：2026-08-07 全稿一致性审查暴露新旧版本混杂的系统性风险（正文沿用旧样本数字、CSV 与表号脱节、无出处数字、do/log 版本错位）。本协议在每轮实证修改中强制执行。

**核心概念：Run Tag**——每次全量重跑或样本口径变更 = 一个运行标记 `YYYYMMDD_vN`（如 `20260807_v3`）。所有产物（CSV 目录、do 归档、log、正文状态行）绑定同一 tag。

> **开新 run 必须走 `stata-regression/scripts/rerun.sh new "<tag>"`**（v0.4.1 强化）：自动归档旧表到 `output/archive/tables_<旧tag>/` → 建 `output/tables/<tag>/` → 更新 MAPPING.md。禁止直接改 CSV 或手动建目录——原地覆盖是追溯失败的根源（2026-08-13 实测：正文 -0.7445 vs CSV -0.8004，137 处不一致因 CSV 被覆盖无从追溯）。do 模板已强制 `global TAG` + `output/tables/$TAG/` 输出路径。

1. **CSV 命名 = 正文表号**：输出至 `output/tables/rerun_<tag>/table<NN>.csv`（NN 为正文表号，如 table04 = 正文表 4）。正文表号重排时同步重命名 CSV；禁止靠"内容匹配"猜对应。
2. **四件套绑定**：一张表 = do 段落 + log + CSV + 正文表格 + 状态行标注，五者缺一即该表数字不可追溯（按 P0 处理）。正文引用表格前先确认四件套齐全。
3. **改数字五步闭环**：改 do → 重跑（log 更新）→ CSV 更新 → 正文表格更新 → 状态行更新。禁止只改正文不重跑、只重跑不改 CSV。do 与 log 的样本口径必须一致（如 keep 条件），不一致视为版本错位。
4. **版本切换协议**：换样本/全量重跑 = 新 tag + 新输出目录，旧目录移入 `archive/rerun_<旧tag>/`，禁止原地覆盖。切换完成后执行**旧值扫描**：grep 旧样本特征值（样本量、关键系数、样本期）确认正文零残留，再更新 docs（数据构造.md/变量说明.md 的样本期与变量清单）。
5. **数字出处纪律**：正文每个数字必须可回溯到 log 或 CSV（记行号）；"历史备忘"类过程文档（如 主回归结果.md 的决策记录）不产出表格数字；无出处数字写入正文 = P0，须重跑补出处。
6. **临时 do 归档**：/tmp 调试 do 跑通后必须归档至 `dofiles/<tag>/`，文件头注明 tag、用途、产出表号；分析命令 README.md 同步登记。
7. **log 强制留存**：每次运行 log 命名 `logs/<tag>/<表号>_<内容>.log`；0 字节 log = 未跑成功 = 该表数字无效，须重跑。
8. **每 run 一份 MAPPING.md**：run 目录内放表号 ↔ CSV ↔ do 段落 ↔ log ↔ 样本口径对照表。同一结果多份日志（不同样本口径）必须标注口径，禁止未标注并存。
9. **正文状态行 = 版本声明**：每章头部状态行写 `> 版本：<tag>（<样本期>）`；任何数字修改后立即更新状态行（含"待补跑"标记的清除）。
10. **一致性审计**：每次会话结束或阶段 5 结束时，跑一次一致性扫描：正文特征值 grep（旧样本量/旧系数/旧样本期）+ 抽查 1-2 张表回读 CSV 逐格核对。审计结果记录到仪表盘迭代记录。

**常见违规模式**（发现即修）：
- 正文用旧样本数字：旧样本量（如 25,300/26,800）或旧系数与 rerun 目录 CSV 不符
- CSV 文件名与表号脱节：正文表 6 的 CSV 叫 full_table3.csv
- 数字只有"历史备忘"出处：log/CSV 中 grep 不到
- do 改了没重跑：do 与 log 的 keep 条件/样本期不一致

## 实证设计惯例（阶段 5 补充，2026-07）

以下为本会话验证过的设计决策，后续论文项目可直接套用。

### V1/V2 的主次关系

DV 有多个度量版本时，**V1 做主回归，V2 做稳健性**。不要 V1+V2 并排两张主回归表。理由：
- CSSCI 主回归 1-2 张表，V1+V2 18 列过于臃肿；
- 「替换 DV 度量后结果不变」是稳健性经典范式，比并列展示更有说服力；
- 全文异质性、平行趋势、IV 也只跑 V1，V2 仅出现在稳健性一节。

### 处理强度：连续得分 > 二元分组

处理变量有天然强度梯度（如大数据局级别×性质 0-5），**用连续得分全样本回归**，不限定 treated 子样本做二元比较。理由：
- 限定子样本后聚类数从 31 降至 15-20，Stata 报警「missing F statistic」；
- 二元分组控制组定义模糊（副厅 vs 正处/挂牌？行政 vs 事业 vs 部门管理？）；
- 连续得分直接放入主回归，作为剂量-反应证据，表格 3-6 列。

### 经济后果与机制的探索顺序

不要一上来就套 `dev×post` 交互项。从简到繁：
1. **直接回归**：`outcome ~ post` 或 `outcome ~ dev`（无交互）
2. **分组**：按 suspect_rd/SOE 等做子样本回归看符号差异
3. **交互项**：`outcome ~ dev×post` 仅在步骤 1-2 有信号时尝试

研发操纵类指标优先用连续变量（RDIN）而非虚拟变量（suspect_rd）。

### 机制检验批量策略（2026-07 验证）

**10+ 条机制的教训：绝大多数 M 的 post→M 就不显著。** 不要逐条跑、逐条等结果。策略：

1. **批量构造 → 批量跑 Step 2**：一次把 5-8 个候选 M 变量全构造好，一个 do 文件全部跑完，只输出 `M ~ post` 的系数和 p 值
2. **p<0.05 的才进入 Step 3**，其余直接废弃，节省轮次
3. **连续变量 > 二元分组**：RDIN > suspect_rd，研发投入强度 > 研发人员占比，分析师跟踪数 > 非标审计意见
4. **已验证可行的一条**：`RDSpendSumRatio ~ post`（研发投入强度，p=0.046，方向正）——来自 CSMAR 研发投入表 `PT_LCRDSPENDING.dta`
5. **同源数据统一 merge**：避免重复加载大 CSMAR 文件
6. **Stkcd 类型注意**：CSMAR 各表 Stkcd 格式不一致（str6 / long / double），merge 前务必检查并统一类型

### 常见死路（直接跳过，不要重试）

3. **新文件自带状态行（2026-08-11 用户要求）**：合并后的 md 文件头部写入自己的状态行，刚生成时**只记录生成时间**（如 `> 状态：2026-08-11 23:36 生成（源稿：06-论文稿/正文/ 10 章合并，状态行剥离，图片自包含于 图片/；正文修改后重新生成并更新本行）`），后续修改再追加内容——不带源稿各章的历史状态
3. **图片自包含（关键）**：正文 md 的图片引用为相对路径 `图片/xxx.png`（位于 `06-论文稿/正文/图片/`）——**将整个图片目录复制到 `07-投稿/投稿版/图片/`**，合并后的 md 保持相对引用即可独立携带（跨设备/分享不断图）
4. **验证（铁律）**：正则提取合并后 md 的全部图片引用（`!\[[^\]]*\]\((图片/[^)]+)\)`）与图片目录文件逐一比对，**缺失 = 0** 才算成功
5. **同步重生成**：正文 md 修改后重跑合并（与 docx 重生成同节奏）
6. **独立演化规则（2026-08-11 用户定案，强制）**：投稿版-正文.md 生成后即**脱离源稿独立存在**——之后对该文件的任何修改**直接编辑文件本身**，**禁止用 `06-论文稿/正文/` 的内容重新合并覆盖或同步**（源稿内容不得污染投稿版）；重新生成仅当用户明确说"重新生成投稿版 md"时执行，执行后按本流程重写状态行

### 7.4 审稿意见处置流程（2026-08-10 定案，K3 三轮审稿验证）

**第一步：审稿外包（建议，非强制）**

投稿前可将全文交由**其他模型**（如 Kimi K3、Claude）独立审查。单一模型存在系统性盲区（训练语料、方法偏好、误判模式），外部模型交叉审查可暴露自审盲点；实操中外部模型亦有误判（简化推理挑战 Stata 实际输出、读错表格结构），故**外包审查的意见仍需逐条核实，不可照单全收**。工具：`cli-agent-delegation` 技能（K3 调用 `~/.kimi-code/bin/kimi -m kimi-code/k3 -p`，任务书 = 全文状态行剥离 + 前轮意见 + 本轮修改说明，输出按 P0/P1/P2 分级 + 通过项确认 + 拒稿理由）。

**第二步：意见分级**

- **P0**：数据/数字/表格硬伤（正文与 CSV 不符、表格破损、断链）——必须立即修
- **P1**：必改（方法表述、论证逻辑、引用错误、样本量口径）——逐条处置
- **P2**：可选（格式、建议性引用、锦上添花）——按用户逐条拍板

**第三步：逐条核实真伪（铁律）**

每条意见先核实再处置，特别是涉及数字的指控：
- 系数/SE/星号 → 从 log 或 CSV 重跑验证（esttab 星号来自实际 p 值，勿用"聚类数 t 临界值"简化推理反驳/接受）
- 表格结构 → 直接读正文表格与 CSV 对照
- 引用 → CNKI/Crossref 查证（chinese-literature 技能）
- 核实方法：写临时 do 重跑，或 read_file 读 CSV 逐格对照
- **驳回需给出证据**（如"重跑验证 p=0.0115 与星号一致，指控不成立"），接受需给出修改

**第四步：处置决策**

| 判定 | 动作 |
|------|------|
| 属实 | 直接修（数字修改走五步闭环：改 do → 重跑 → CSV → 正文 → 状态行） |
| 误判 | 驳回，附重跑/核对证据 |
| 涉及叙事/结构 | 列方案给用户拍板（如"dev_nord 升格 vs 维持稳健性"） |

**第五步：复核闭环**

全部处置完成后：
- grep 旧值零残留（旧系数/旧样本量/旧表述关键词）
- 抽查 2-3 处修改点读回文件确认
- 状态行 + 主回归结果.md + 写作备忘同步更新
- 重大处置记录到研究发现/（如"费舍尔 1000 次重跑暴露均值回归分组口径错误"）

**第六步：响应信（response letter）**

逐条回复格式：`意见原文摘要 → 处置（修改/驳回+证据/部分采纳）→ 修改位置（章节/表号）→ 修改后数字`。驳回项必须给出可验证的证据链（log 行号/CSV 单元格/重跑输出），不写"感谢指出"式空话。

**教训沉淀（2026-08-10）**：
- 外部模型误判实例：P1-11 用"31 聚类 t 临界值 2.75"质疑星号——重跑验证 p=0.0115 与 ** 一致，驳回
- 重跑暴露真实问题实例：费舍尔从 200 次升 1,000 次重跑，暴露均值回归分组口径错误（pre3>4.95 常数 vs 2015-2017 窗口企业中位数 5.1711）与论证逻辑缺陷（均值回归恰恰预测高位组降幅更大），p 从 0.005 翻转为 0.106，正文论证整体改写——**重跑是审稿处置的照妖镜**
- 正则会伤英文：去卷号正则作用域 bug 误删英文节 17 条卷号，朗读测试才暴露——**批量替换前先圈定作用域，改完全文复查**

**第七步：最终版数据存档（全部审稿流程完成后的最后一步）**

所有审稿意见处置完毕、正文定稿后，生成可复现全部结果的最终版数据包：

1. **位置**：`数据/working data/final/`（不存在则创建；父路径含空格时所有命令加引号）
2. **内容**：working data 主数据（.dta）+ 全部 do 文件（构造/主链/稳健性）+ 对应 logs + 表格 CSV + README.md
3. **README 必备五要素**：复现链（按序运行顺序）、关键 do 索引（检验 ↔ do ↔ 正文表号）、固定设定（随机种子/聚类层级/样本期/变量口径）、复现基准锚点表（关键数字清单，供校验对照）、已知边界（原始数据不在包内、绝对路径需调整）
4. **存档校验（铁律）**：用存档数据重跑基准回归，与正文关键数字逐位一致（系数/SE/样本量）才算存档成功；不一致 → 追查数据版本错位，不得带着不一致存档
5. **清理**：调试残留临时文件（test_*、*_tmp 等）不进 final
