# Research Discovery — 实证研究发现管理

## 定位

实证研究本质是实验室工作：结果意外不是异常，而是研究过程的核心信息源。本技能把「意外结果 → 系统诊断 → 假设修正 → 知识沉淀」做成固定流程，防止两种常见失败：

- 看到不显著就急着改模型（p-hacking 滑坡）
- 意外发现只留在会话里没有沉淀，下篇论文重复踩坑

**与 paper-workflow 的分工（深度配合）：**

| 侧 | 负责方 | 内容 |
|----|--------|------|
| 发现侧 | 本技能 | 触发 → 诊断 → 差距分析 → 决策 → 沉淀（Obsidian `研究发现/`） |
| 论文侧 | paper-workflow | 假设更新、表格更新、仪表盘、阶段回退（Obsidian `论文写作/`） |

协作流程：
1. paper-workflow 阶段 5 出现意外结果 → 加载本技能，进入发现流程
2. 本技能产出诊断结论与决策建议（修改假设 / 调整设计 / 放弃）
3. 决策执行落到论文侧：按 paper-workflow「阶段 5→2 回写」规则修改理论推演.md、研究计划.md 等
4. 双向 wiki-link 记录因果链（为什么做这次发现、这次发现改了哪里）

## 触发条件

- 主回归 / 机制 / 平行趋势 / 稳健性结果与假设不符（不显著、符号反转、部分显著）
- 意外显著（没假设过的关系显著了）
- 审稿人质疑实证结果，需要重新审视
- 数据探索中发现新规律，可能孵化新选题
- 用户说"这个结果怎么回事""为什么""帮我解释一下"

## 六步流程

### Step 1 冻结结果（先做，不可跳过）

调模型之前，先把原始证据固化：

- log 文件路径、CSV 单元格、系数 / 标准误 / 样本量
- 当前 do 文件版本（git 或复制备份）

理由：不冻结，调完模型原始发现就丢了，事后无法判断是数据真相还是人为选择。

### Step 2 分层诊断

从下往上逐层排除，每层给出「排除 / 定位」结论，必须有证据（log、样本量对比），不能"觉得没问题"：

1. **数据层**：测量误差、样本切换（条件子样本成员是否改变）、merge 膨胀（_merge==3 比例）、winsorize 异常、变量构造错误
2. **方法层**：识别策略缺陷、规格设定（FE / 聚类 / 控制变量）、处理变量定义、期数归并
3. **理论层**：假设方向错误、机制链断裂、存在未预期的替代解释

方法层需要外部实操方案时 → 加载 `research-media-skill` 搜经管之家。论坛是诊断流程里的工具，不是全部。

### Step 3 差距分析

- 我们假设了什么（H 的完整逻辑链 X → M → Y）
- 数据实际说了什么（系数、符号、显著性、异质性模式）
- 差异本身是信息：事前显著 + 事后符号反转、机制 Step 2 不显著，都蕴含可讲的故事

### Step 4 机制探索

机制层面的疑问 → 读 `paper-workflow` 的 `references/mechanism-exploration-protocol.md`（Step A-E 顺序执行，禁止跳过 Step A/B 直接跑交互项——没有直接效应基础就上交互项等于盲试）。

### Step 5 决策路由

| 诊断结论 | 路由 | 论文侧动作 |
|---------|------|-----------|
| 数据层问题 | 回阶段 4 | 修构造，重跑 |
| 方法层问题 | 回阶段 3 | 调整识别策略 |
| 理论层：假设错 | 回阶段 2 | 修正假设（理论推演.md） |
| 理论层：新机制 | 阶段 5 继续 | 新增机制检验 |
| 新问题 / 新关系 | 阶段 0 | 记入选题孵化 |
| 无法解释 | 如实记录 | 论文中如实说明 |

### Step 6 沉淀（强制）

- 发现文件归档：`研究发现/01-发现/F-序号-标题关键词.md`（完整生命周期，模板见 `_研究发现模板/01-发现/_F-模板.md`）
- 聚合更新：`02-假设修正.md` / `03-选题孵化.md` / `04-方法论沉淀.md`
- 跨论文可复用经验 → agent memory/学术/_方法/（Obsidian 长期记忆路由）

## Obsidian 文件结构

```
研究/<项目名>/
├── 研究发现/                  ← 本技能空间
│   ├── 00-发现索引.md         ← 看板：发现清单 + 状态
│   ├── 01-发现/F-xxx.md       ← 每条发现一个文件（完整生命周期）
│   ├── 02-假设修正.md         ← 聚合：假设修正史
│   ├── 03-选题孵化.md         ← 聚合：孵化中的新选题
│   └── 04-方法论沉淀.md       ← 聚合：跨论文可复用经验
└── 论文写作/                  ← paper-workflow 空间（00-项目仪表盘.md + 01~07 阶段）
```

新建项目：从 `_研究发现模板/` 复制整套结构（00 + 01-发现/ + 02 + 03 + 04），`01-发现/` 内放 `_F-模板.md` 副本作为命名参考（下划线前缀避免被误计为真实发现）。

## wiki-link 双向索引规范（强制）

- 发现文件「1. 触发」段链接论文侧触发文件（为什么做）：
  `[[研究/<项目名>/论文写作/05-实证/机制检验]]`
- 发现文件「4. 决策与影响」段链接被修改的论文侧文件（改了哪里）：
  `[[研究/<项目名>/论文写作/03-理论/理论推演]]`
- 论文侧修改处追加反向标注：`> ⚠️ 依据 [[F-001-平行趋势异常]] 修正（2026-07-31）`
- 发现文件命名：`F-序号-标题关键词.md`（如 `F-001-平行趋势异常.md`），序号**项目内递增**（每个项目从 F-001 起）
- ⚠️ **反向链接必须写完整文件名**：`[[F-001]]` 解析不到 `F-001-平行趋势异常.md`，会断链；链接**不带 `.md` 后缀**（Obsidian 按文件名自动补全）
- ⚠️ Obsidian 路径型 wiki-link 按 vault 根解析：必须写 `[[研究/<项目名>/论文写作/...]]` 完整路径，`[[论文写作/...]]` 会断链
- Obsidian backlinks 自动形成双向视图。**论文侧文件只链接不复制**——发现内容不搬进论文文件，论文内容不搬进发现文件

## 铁律

- 先冻结结果，再动模型
- 禁止用换基期 / 归并期数 / 硬套 PSM 糊弄替代机制理解。DID 异常模式（如事前显著 + 事后符号反转）要用前沿方法提取信息：HonestDiD（Rambachan & Roth 2023）敏感性分析、处理组线性趋势——异常模式本身可能蕴含理论信息
- 条件子样本（如 ε<0 才入样）的平行趋势问题标准修复：改非条件 DV（如 under_intensity=max(0,-ε)）全样本跑，成员切换假象自动消失
- 每条死路必须记录（发现文件或方法论沉淀），防止重复试错
- 决策路由前必须自查检验内部有效性：对照组样本量够不够、系数由谁识别、条件子样本成员是否切换
